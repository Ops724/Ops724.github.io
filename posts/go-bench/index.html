Go 语言测试框架 testing 基准测试

中 EN

testing 是标准库提供的一个内置包，专门用于编写和运行自动化测试。它提供了一套完整的测试框架，帮助开发者验证代码的正确性、稳定性和性能。

基准测试（Benchmark）

评估代码性能（操作耗时）。

使用规范

  • 测试文件命名：测试文件必须以 _test.go 结尾（这些文件在 go build 时会被忽略，不会被编译到最终的可执行文件中），通常与被测试的源文件放在同一个包目录下（例如，测试 math.go 则创建 math_test.go）。
  • 测试函数签名：必须以 Benchmark 开头，且参数必须是 *testing.B。例如：func BenchmarkXxx(b *testing.B)。

go test 命令

go test -bench=. 运行所有基准测试（默认情况下 go test 基准测试函数不会被执行）。

示例

package main

import "testing"

// 要测试的目标函数（通常放在其他文件中，这里为了示例写在同一个文件）
func Add(a, b int) int {
    return a + b
}

func BenchmarkAdd(b *testing.B) {
    // b.N 由 go test 自动调整，保证稳定测量
	for i := 0; i < b.N; i++ {
	    Add(1, 2)
	}
}

运行基准测试

go test -bench=.

  • BenchmarkAdd-10：-10 代表使用的 cpu 核心数（由 GOMAXPROCS 决定）。
  • 1000000000：表示执行次数（即 b.N 的值）。
  • 0.2353 ns/op：表示每次操作的平均耗时。

为什么要加 for i := 0; i < b.N; i++ ？因为：

  • go test 计算性能的方式是：测量执行整个循环所花的总时间除以 b.N，得到 ns/op，即每次操作的平均耗时。
  • 如果去掉这个循环，基准测试函数只执行一次 Add(1, 2)，此时总耗时可能极短（0.1 纳秒），CPU 的时钟精度无法精准测量，结果会显示 0.00 ns/op，使得测试完全失去参考意义。框架依赖这个循环来获得可测量的总时间。
  • 基准测试函数如果只执行一次，在统计学上叫单次采样，结果极易受当前 CPU 频率、后台其它进程干扰，结果极为不稳定。

b.N 自适应机制，它并不是固定值，而是由测试框架动态调整的。

  • 运行基准测试时，go test 会先让 b.N = 1 跑一次。
  • 如果耗时太短（默认少于 1 秒），它会自动将 b.N 乘以一个倍数（比如 100 倍），然后重新运行整个测试函数。
  • 如此反复，直到整个循环总耗时达到约 1 秒（或其它设置的值）。

所以，这个循环的目的是为整个框架提供一个可以重复执行的代码块，让框架通过调节执行次数来获得足够大且稳定的总时间样本，从而计算出精确的单次操作耗时。

如果手动写死循环次数 for i := 0; i < 10000; i++ 可以吗？不行，因为：

  • 如果写死 10000 次，在性能差的机器上测试可能跑 1 秒，在性能强的机器上可能只跑 0.001 秒。
  • 这样算出来的 ns/op 会随着硬件变化剧烈波动，无法跨平台对比，也无法用来做性能回归分析。
  • 使用 b.N 框架才能根据当前机器的性能自动调整次数（比如慢机器上跑 1000 次，快机器上跑 1000000 次），最终保证每次操作 ns/op 的数值是稳定且可比较的。
