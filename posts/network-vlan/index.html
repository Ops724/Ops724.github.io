利用 Linux 网络虚拟化理解 VLAN 技术

2026-07-28 网络技术 #vlan
中 EN

这是一篇写于当时语境下的技术记录。技术发展日新月异，若其中某些方法、结论或版本信息已经过时，就把它当作一次技术考古吧。

硬件：Apple M4
系统：Mac OS Tahoe 26.3
VMware Fusion：Professional 26H1（25388279）
虚拟机 OS：Ubuntu 26.04 LTS

完整的 VLAN 实验，只需一台 Linux 主机（物理机虚拟机均可），无需任何物理交换机。

  • 使用网络命名空间（Network Namespace）模拟多台主机。
  • 使用 Linux Bridge 模拟二层交换机。

实现拓扑与目标

拓扑

  • vlan 10：包含主机 host1、host2，子网 “10.0.10.0/24”
  • vlan 20：包含主机 host3，子网 “10.0.10.0/24”

最终实验目标

  1. 同一 VLAN 内主机能 ping 通（host1 -> host2）。
  2. 不同 VLAN 内主机不能 ping 通（host1 -> host3）。

创建网桥并启用 VLAN 过滤（相当于二层交换机）

创建网桥（相当于交换机）。

# 创建网桥，并开启 vlan_filtering 和 vlan_default_pvid
sudo ip link add br0 type bridge vlan_filtering 1 vlan_default_pvid 1
# 启用网桥
sudo ip link set br0 up

创建网络命名空间（模拟主机）并连接至网桥

创建 4 个主机命名空间，并通过 veth 对连接到对应的网桥。

# 创建 host1（vlan10）
## 创建 host1 命名空间
sudo ip netns add host1
## 创建一对虚拟以太网设备（veth pair），分别命名为 veth1a、veth1b，veth 总是成对出现，类似一根“虚拟网线”连接两端。
sudo ip link add veth1a type veth peer name veth1b
## 将 veth1b 这个网络接口设置为网桥 br-vlan10 的一个从属端口（slave）
sudo ip link set veth1b master br0
## 激活 veth1b 接口
sudo ip link set veth1b up
## 将 veth1a 这个接口移动到命名空间 host1 中
sudo ip link set veth1a netns host1
## 在命名空间 host1 内部执行 ip link set veth1a up，激活 veth1a
sudo ip netns exec host1 ip link set veth1a up
## 在 host1 内部为 veth1a 接口分配 IP 地址。
sudo ip netns exec host1 ip addr add 10.0.10.1/24 dev veth1a

# 创建 host2（vlan10）
sudo ip netns add host2
sudo ip link add veth2a type veth peer name veth2b
sudo ip link set veth2b master br0
sudo ip link set veth2b up
sudo ip link set veth2a netns host2
sudo ip netns exec host2 ip link set veth2a up
sudo ip netns exec host2 ip addr add 10.0.10.2/24 dev veth2a

# 创建 host3（vlan20）
sudo ip netns add host3
sudo ip link add veth3a type veth peer name veth3b
sudo ip link set veth3b master br0
sudo ip link set veth3b up
sudo ip link set veth3a netns host3
sudo ip netns exec host3 ip link set veth3a up
sudo ip netns exec host3 ip addr add 10.0.10.3/24 dev veth3a

测试下连通性

当前未设置 VLAN，三台主机同广播域可以互通。

# host1 -> host2
sudo ip netns exec host1 ping -c 2 10.0.10.2
# host2 -> host3
sudo ip netns exec host2 ping -c 2 10.0.10.3
# host3 -> host1
sudo ip netns exec host3 ping -c 2 10.0.10.1

配置端口 VLAN

这里有一个知识点，在交换机属于中 Access 接口是指连接终端（如 PC、服务器、打印机）的端口。它有两条核心行为：

  1. 收包时：如果收到不带标签的普通数据帧，则打上该端口所属 VLAN 的标签（PVID）。
  2. 发包时：在将数据帧发送给终端设备前，必须剥离 VLAN 标签（因为终端设备的网卡通常不识别也不处理 802.1Q 标签）。

下面命令中 pvid、untagged 含义就是指定接口的 Access 行为。

# 将 veth1b 划入 vlan 10，access 端口
sudo bridge vlan add dev veth1b vid 10 pvid 10 untagged 10
# 将 veth2b 划入 vlan 10，access 端口
sudo bridge vlan add dev veth2b vid 10 pvid 10 untagged 10
# 将 veth3b 划入 vlan 20，access 端口
sudo bridge vlan add dev veth3b vid 20 pvid 20 untagged 20

# 查看当前配置
bridge vlan show

验证隔离效果

# host1 -> host3 预期效果不通
sudo ip netns exec host1 ping -c 2 10.0.10.3
# host1 -> host2 预期效果通
sudo ip netns exec host1 ping -c 2 10.0.10.2


在这个实验中：

  • veth1b 配置为 pvid 10、untagged 10，但是 host1 的网卡 veth1a 完全感知不到 VLAN 标签，它只觉得自己在普通的 10.0.10.x 网段里通信。
  • veth3b 配置为 pvid 20、untagged 20，host3 的网卡 veth3a 也感知不到标签，但其属于 VLAN 20。

因为网桥内部严格检查 VLAN ID，所以 host1 发出的无标签帧进入网桥后被标记为 VLAN 10，无法转发到只允许 VLAN 20 的 veth3b 端口，实现了完美隔离。

VLAN 间通信

在上述实验基础上，通过单臂路由实现 VLAN 间的通信。

修改当前环境中 VLAN 20 host3 IP

# 删除 host3 当前 IP
sudo ip netns exec host3 ip addr del 10.0.10.3/24 dev veth3a
# 配置新 IP，VLAN 20 网段 10.0.20.x/24
sudo ip netns exec host3 ip addr add 10.0.20.1/24 dev veth3a


创建路由命名空间及 Trunk 链路

创建一个名为 router 的命名空间，并用一根 veth “网线” 将它连接到网桥 br0 上。这根网线在网桥侧配置为 Trunk 口，允许 VLAN 10 和 20 的标签通过。

# 创建路由器命名空间
sudo ip netns add router
# 创建 veth 对
sudo ip link add veth-s-r type veth peer name veth-r-s
# 将 veth-s-r 接入网桥 br0
sudo ip link set veth-s-r master br0
sudo ip link set veth-s-r up
# 将 veth-r-s 移入路由器命名空间
sudo ip link set veth-r-s netns router
sudo ip netns exec router ip link set veth-r-s up

配置网桥侧 Trunk 口，路由器侧子接口

网桥侧：将 veth-s-r 设为 Trunk 口，允许 VLAN 10 和 20 通过（不加 untagged，保留标签）。

# 允许 VLAN 10 和 VLAN 20 的带标签帧通过
sudo bridge vlan add dev veth-s-r vid 10
sudo bridge vlan add dev veth-s-r vid 20

路由器命名空间内部：在 veth-r-s 上，创建两个 VLAN 子接口，分别对应 VLAN 10 和 VLAN 20，并配置网关 IP。

# 创建 VLAN 10 子接口（接收打了 10 标签的帧）
sudo ip netns exec router ip link add link veth-r-s name veth-r-s.10 type vlan id 10
sudo ip netns exec router ip link set veth-r-s.10 up
sudo ip netns exec router ip addr add 10.0.10.254/24 dev veth-r-s.10

# 创建 VLAN 20 子接口（接收打了 20 标签的帧）
sudo ip netns exec router ip link add link veth-r-s name veth-r-s.20 type vlan id 20
sudo ip netns exec router ip link set veth-r-s.20 up
sudo ip netns exec router ip addr add 10.0.20.254/24 dev veth-r-s.20

开启路由转发并配置主机网关

开启路由转发：让路由器命名空间具备转发 IP 包的能力。

sudo ip netns exec router sysctl -w net.ipv4.ip_forward=1

配置主机默认网关：让各 VLAN 内的主机把数据包发给路由器。

# host1 和 host2（VLAN 10）的网关指向 10.0.10.254
sudo ip netns exec host1 ip route add default via 10.0.10.254
sudo ip netns exec host2 ip route add default via 10.0.10.254

# host3 的网关指向 10.0.20.254
sudo ip netns exec host3 ip route add default via 10.0.20.254

验证 VLAN 间通信

从 host1（VLAN 10）ping host3（VLAN 20），成功。

sudo ip netns exec host1 ping -c 2 10.0.20.1
